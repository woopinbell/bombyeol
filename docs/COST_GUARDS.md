# Bombyeol — 비용 방어 게이트 (불변 원칙)

hamkke의 운영 리스크 점검(2026-09-27)에서 코드 리딩만으로 찾은 금전 리스크를 **봄별의 설계 제약**으로 옮긴 문서다. "출시 전에 막는다"가 아니라 **각 기능 커밋의 완료 조건**이다: 기능을 구현하는 커밋은 해당하는 게이트를 함께 만족하고 그 테스트를 포함해야 한다.

> 위협 모델: 가입은 카카오/Google 계정만 있으면 누구나 가능하고, 계정 두 개로 자기들끼리 Space를 만들면 정상 Space가 된다. 즉 **"가족 전용 앱"이라는 구조가 공격자를 막아주지 않는다.** 무료 사용자도 저장소를 클라우드처럼 쓰려는 시도를 전제한다.
>
> **Cloudflare는 하드 지출 상한이 없다**(예산 알림은 정보성이며 사용을 멈추지 않는다 — 2026-10-01 확인). 그래서 이 문서의 앱 레벨 상한이 사실상 유일한 자동 방어선이다.

## 1. 게이트 목록

| ID | 게이트 | hamkke에서 발견된 리스크 | 봄별의 방어 | 검증 테스트 |
|---|---|---|---|---|
| G-01 | 업로드 크기·형식 상한 | 서명에 ContentLength 없음 → 5GB까지 임의 바이트 업로드 | `requestUpload`가 선언 bytes를 상한(이미지 10MB·영상 50MB 등, `plan.ts`)과 대조, 서명(또는 Worker 프록시)이 그 크기를 강제, Content-Type 화이트리스트 | 선언보다 큰/다른 타입 PUT 거부 |
| G-02 | 업로드 확인·소유 검증 | 키 문자열을 신뢰 → 남의 파일 참조 가능 | `MediaAsset` pending→confirmed(HeadObject로 크기·실존), 참조 mutation은 **자기 Space의 confirmed 자산 ID**만 수용 | 타 Space 자산·pending 자산 참조 거부 |
| G-03 | Space 총 저장 상한 | 총량 제한 없음 | confirmed 바이트 합계 상한(무료·프리미엄 모두), 초과 시 새 업로드만 거부 | 상한 경계값 |
| G-04 | 업로드 URL 발급 횟수 제한 | URL만 받고 안 써서 한도 우회·남용 | Space·사용자별 발급 횟수 제한(시간 창), 미확정 자산 수 상한 | 초과 시 429 |
| G-05 | 삭제 = 객체 삭제 | DB 행만 지우고 R2 파일 잔존 → 비용 누적, "지우고 다시 올리기" 우회 | 삭제 시 R2 객체도 삭제(실패 시 재시도 큐), `pending/` 수명주기 규칙 + Cron 정리 | 삭제 후 객체 없음, 고아 정리 |
| G-06 | 계정·Space 삭제 | 삭제 기능 자체가 없음 → 저장 비용 영구 누적, 스토어 심사·개인정보 파기 의무 위반 | 앱 안 + 웹 URL 양쪽에서 계정 삭제·Space 삭제, R2 전체·DB·구독 해지 연쇄, `DeletionRequest` 기록(유예 기간 정책은 `PRIVACY_AND_LEGAL.md` §5) | 삭제 후 잔존 데이터 0, 구독 해지 호출 |
| G-07 | 쓰기 API 레이트 리밋 | 로그인·채팅·위치 등 무제한 | 로그인 시도, 초대 입력, 업로드 발급, 반응/댓글 작성, 이야기 작성, 결제 세션 생성에 리밋(방식은 S-6). 이메일 매직링크는 아예 없음(메일 폭탄 리스크 제거) | 초과 시 429 |
| G-08 | 클라이언트 직접 통신 채널 없음 | 공개 Realtime 채널에서 서버 우회 무한 브로드캐스트·가짜 이벤트 | 실시간 채널을 두지 않는다. 향후 도입 시 private 채널 + 서버 서명 토큰이 선결 | — (구조적 제거, ARCHITECTURE §1) |
| G-09 | 구독 동기화 정합성 | 재구독 시 spaceId unique 충돌 → 웹훅 500, 결제 성공 + 앱은 무료; 이중 Checkout 이중 청구 | 구독을 **spaceId 키로 upsert**, 진행 중 세션 재사용 + 멱등성 키, 활성 구독 시 신규 세션 거부, 웹훅 서명 검증·멱등 처리 | 해지→재구독 시나리오, 동시 Checkout |
| G-10 | 외부 API 상업 라이선스 | Open-Meteo 비상업 무료 티어, OSM 공개 타일을 상업 앱에서 사용 | 봄별 V1에는 지도·날씨가 없다. **외부 API를 추가할 때마다 상업 이용 조항을 문서에 먼저 기록**하고 승인 후 도입 | (체크리스트) |
| G-11 | 계정·Space 남용 | 계정 다수 생성으로 무료 티어 증식 | 사용자당 Space 생성 수 상한, Space당 멤버 수 상한, Space당 아이·반려동물 수 상한, 삭제된 Space의 재생성 쿨다운, 초대 brute-force 방지(`InviteCodeAttempt`) | 상한 경계값 |
| G-12 | 예산 알림 (운영 체크리스트) | 대시보드 설정은 코드로 확인 불가 | 아래 §4 체크리스트를 릴리스 전에 사용자가 직접 확인 | (수동) |
| G-13 | PDF 내보내기 비용 | — | 클라이언트 생성 우선, 서버 생성 시 횟수·크기 상한과 프리미엄 게이트 | 한도 초과 거부 |
| G-14 | STT/AI 호출 비용 (후속) | — | 프리미엄 한정, 클립 길이·월 호출 수 상한, 실패 재시도 상한. **이 게이트가 없으면 음성 기능을 켜지 않는다** | 상한 |
| G-15 | 사용량 가시성 | 과금을 사후에 발견 | `UsageCounter`로 Space별 저장·발급·내보내기를 집계, 이상치(급증)를 Cron이 로그로 남김 | 집계 정확도 |
| G-16 | 건당 과금 채널 금지 | — | 알림톡·친구톡·SMS 등 건당 과금 채널은 도입하지 않는다. 필요해지면 비용 상한과 함께 사용자 승인 | (원칙) |
| G-17 | 위치·로그성 데이터 누적 | 위치 핑이 무제한 누적 | 봄별은 위치를 저장하지 않는다. **시계열/로그성 테이블을 추가할 때는 보관 기간·상한을 스키마 설계에 포함** | (원칙) |

## 2. 게이트를 커밋에 붙이는 방법

- `COMMIT_PLAN.md`의 각 기능 항목에 관련 게이트 ID가 표기되어 있다. 그 항목을 구현할 때 게이트 테스트가 같은 커밋 또는 직후 `test(...)` 커밋에 들어가야 한다.
- 게이트를 일시적으로 완화해야 하면(예: 개발 편의) 코드에 `TODO(G-xx)`를 남기고 `PROGRESS.md`에 기록한다 — 출시 전 체크리스트에서 반드시 회수한다.
- 새 위험 경로(새 외부 서비스·새 저장소·새 쓰기 API)를 도입하기 전에 이 표에 행을 추가한다.

## 3. 최악 비용 시나리오 (가정 기록, 단가는 착수 시 재확인)

| 시나리오 | 방어 전 | 방어 후 상한 |
|---|---|---|
| 계정 N개로 각자 Space를 만들고 R2를 클라우드 저장소로 사용 | 크기 무제한 × 횟수 무제한 → 예: 5TB ≈ 월 $75 이상이 지속 청구(hamkke 계산) | Space당 2GB(무료) × 사용자당 Space 상한 × 계정 생성 속도 — **계정 생성 자체에 레이트 리밋(G-07/G-11)**. 실제 총량 상한은 전체 저장 임계 알림(§4)으로 이중화 |
| 업로드 URL만 무한 발급 | 미확정 객체 누적 | 발급 횟수 제한 + `pending/` 1일 수명주기 |
| 쓰기 API 폭주 | DB·Workers 요청 과금 | 레이트 리밋, 요청 크기 제한 |
| 결제 카드 테스트 악용 | 분쟁 수수료 | Checkout 생성 레이트 리밋 + 결제 공급자의 사기 방어 설정(공급자 확정 후) |
