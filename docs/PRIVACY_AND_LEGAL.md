# Bombyeol - 개인정보, 법적 설계

> **이 문서는 설계 기준이지 법률 자문이 아니다.** 아래 법 조항, 요건은 착수 시점(출시 전)에 최신 법령, 가이드라인과 전문가 검토로 재확인한다. 확인이 필요한 항목은 "(확인 필요)"로 표시했다. 방향은 사용자 결정(2026-10-01): 아동, 임신, 음성, 고인 데이터 처리를 **초기 설계에 포함**한다.

## 1. 데이터 분류

| 데이터 | 주체 | 민감도 | 비고 |
|---|---|---|---|
| 아이 이름, 생일, 사진, 영상, 성장 수치 | **아동**(14세 미만이 대부분) | 높음 | 부모(법정대리인)가 입력 |
| **임신 기록**(초음파, 주차, 검진) | 임신 당사자(주로 부모) | **매우 높음 - 건강 정보** | 별도 동의, 열람 제한 필요(확인 필요: 민감정보 해당 여부와 동의 방식) |
| 어르신 이야기(텍스트) | 어르신 | 높음 | 삶의 기억, 타인 언급 포함 가능 |
| 어르신 음성(후속) | 어르신 | 높음 | 식별 목적이 아니면 생체정보는 아님(확인 필요) |
| 고인의 이야기, 사진 | 고인 + 유가족 | 높음(정서) | 아래 §5 |
| 반려동물 정보, 사진 | 반려동물(법적 개인정보 아님) | 낮음 | 단, 사진에 사람, 집 내부, 위치 단서가 찍힐 수 있어 미디어 일반 원칙을 그대로 적용. 동물 의료 기록은 V1 범위 밖 |
| 로그인 식별자(카카오/Google ID, 이메일, 닉네임) | 사용자 | 보통 | 최소 수집 |
| 푸시 토큰 | 사용자 | 낮음 | 삭제 시 파기 |

## 2. 원칙

1. **비공개 기본**: 모든 콘텐츠는 Space 멤버에게만. 공개 URL, 검색, 추천 없음.
2. **최소 수집**: 카카오 이메일 동의항목은 꼭 필요할 때만(비즈 앱 전환이 필요하므로 이메일 없이 동작하는 설계를 우선 검토 - `ARCHITECTURE.md` §3).
3. **부모가 보호자**: 아이 데이터는 `parent` 역할이 등록, 관리한다. 아이가 14세 이상이 되는 시점의 동의 재취득 방식은 후속 설계(확인 필요).
4. **명시적 동의 기록**: 가입 시 이용약관, 개인정보 처리방침, 아이 정보 처리(법정대리인 동의), **임신(건강) 정보는 별도 동의**를 화면에서 받고 `Consent`(누가, 무엇에, 언제, 버전)로 기록한다.
5. **삭제할 수 있어야 한다**: 앱 안과 웹 URL 양쪽에서 계정 삭제, Space 삭제. 삭제 시 R2 객체, DB, 푸시 토큰, 구독 해지까지 연쇄(G-06). Google Play는 계정 생성 앱에 앱 내 삭제 + 웹 삭제 링크를 요구한다(hamkke 점검에서 확인, Android 착수 시 재확인).
6. **국외 이전 고지**: Cloudflare/DB 공급자 리전이 국외일 수 있다. 처리방침에 위탁, 국외 이전 항목을 명시하고, 가능하면 아시아 리전을 고른다(R2 위치 힌트, DB 리전 - 스파이크 S-1에서 선택 기록).
7. **로그에 개인정보를 남기지 않는다**: 서버 로그에 이야기 본문, 이름, 토큰을 찍지 않는다. 세션 대화 기록(devlog)에 키, 개인정보를 붙여넣지 않는다.

## 3. 임신, 건강 정보 설계

- `PregnancyRecord`는 `visibility`(`parents_only` | `family`)를 가진다. 기본값은 `parents_only`(보수적), 부모가 항목 단위로 가족 공개를 선택.
- 서버가 `visibility`를 강제한다(클라이언트 필터 금지). 관련 tRPC 프로시저 테스트 필수.
- 동의: 임신 기록 기능을 처음 켤 때 별도 안내, 동의(`Consent`) 필요. 철회 시 해당 기록 삭제 옵션 제공.
- 알림, 공유 미리보기(푸시 본문, 카카오톡 공유 카드)에 **민감한 문구를 넣지 않는다**("초음파 사진이 올라왔어요" 대신 "새 소식이 있어요").

## 4. 아동 관련

- 아이 사진, 영상은 부모가 올린다. 조부모, 친척은 열람, 댓글 위주.
- 다른 Space로의 자동 공유 금지(양가가 각자 Space를 만들 경우 부모가 명시적으로 초대).
- **사진 위치 정보 제거(2026-10-02 구현)**: 사진은 올리기 전에 브라우저가 JPEG로 다시 인코딩해 EXIF(GPS 위치 포함)가 지워진다. 촬영 시각만 먼저 읽어 기록 날짜로 쓴다. **영상은 그대로 올라가 위치 메타데이터가 남을 수 있다** - 서버 변환 없이 지울 방법은 미해결(열린 과제).
- 아이 얼굴이 포함된 콘텐츠의 **외부 공유 링크는 만들지 않는다**(카카오톡 공유는 앱 딥링크 + 로그인 필요).
- 처리방침에 아동 정보 처리 항목, 법정대리인 권리(열람, 정정, 삭제) 절차를 넣는다(확인 필요).

## 5. 별이 되신 분(고인) 정책

- 콘텐츠의 소유는 Space(가족)이며 계정과 분리된다. 어르신 계정이 사라져도 이야기는 남을 수 있어야 하므로, **작성자 표시는 Member가 아니라 스냅샷 이름을 함께 저장**(`authorNameSnapshot`)한다.
- "기념" 전환은 `parent` 권한으로만, 되돌릴 수 있게 한다. 기념 상태에서는 새 이야기 작성 불가, 추모 반응만 허용.
- **구독 만료, Space 삭제 유예와 무관하게 기억을 즉시 파기하지 않는다**: 결제 만료 → 읽기 전용 + 다운로드(PDF, 원본 ZIP)를 유지. Space 삭제는 명시적 확인 + 유예 기간(예: 30일, 정책 확정 필요) 후 파기, 유예 중 내보내기 제공.
- 고인 계정 승계, 사후 접근 권한은 다루지 않는다(플랫폼별 정책 상이). 필요해지면 `OPEN_QUESTIONS.md`에 안건으로 올린다.
