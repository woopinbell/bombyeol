## 3. 폴리싱 사다리 — 어디까지 나아질 수 있나

"만 번 깎기"를 단계로 나누면 지금 목업은 **L0~L1 사이**다. 단계마다 무엇이 나아지는지, 무엇이 막고 있는지:

| 단계 | 하는 일 | 나아지는 것 | 막는 것 |
|---|---|---|---|
| L0 구조 | 흐름·위계·문구 초안 (**지금**) | 무엇을 만들지 합의 | — |
| L1 규칙 정합 | 대비·크기·터치를 숫자로 검증(자동 테스트) | 어르신이 "못 읽는/못 누르는" 실패 제거 | 토큰 확정 |
| L2 시스템 | 4/8 간격 스케일, 한글 타입 스케일(행간·자간), 라운드 2~3종, 심볼과 같은 획의 **자체 아이콘** | "흔한 앱" → "한 사람이 디자인한 앱". 눈에 보이는 차이가 가장 큰 구간 | 안 선택, 로고(Q-LOGO)·손글씨(Q-FONT) |
| L3 실물 | 진짜 사진·긴 이름·빈 화면·오류·로딩·글자 200%·320px 폭 | 실제로 깨지는 곳 발견. 목업에서 예쁜 것의 절반은 여기서 무너진다 | UI 구현 |
| L4 모션·촉감 | 시트·boop·sparkle·누름 피드백을 저가 안드로이드에서 60fps로 | Emil·Rauno·Josh 앵커가 처음 "보이는" 단계 | 모션 토큰 확정 |
| L5 실사용 | 어르신 3~5명 관찰(말 없이 써 보게) | **사용성 향상이 가장 큰 구간**. 픽셀로는 못 얻는다 | Q-ELDER(테스트할 어르신) |
| L6 만 번 깎기 | 아이콘 광학 정렬 1px, 한글 의미 단위 줄바꿈, 숫자 고정폭, 사진 로딩 전환, 다크에서 사진 밝기, 스크린리더 문장, 실수 되돌리기의 문장 하나하나 | 사용자가 이유를 말하진 못해도 "이 앱은 다르다"고 느끼는 것(Rauno의 "보이지 않는 디테일") | 끝이 없다 — 완료 선언하지 않는다(CLAUDE.md) |

정직한 답:
- **눈으로 보이는 품질**은 L2까지 가면 지금과 확연히 다르다(가장 가성비 좋은 구간). 지금 목업은 "색만 봄별"이다.
- **어르신이 실제로 쓰는 품질**은 L3·L5에서 가장 크게 오른다. 픽셀을 아무리 깎아도 L5를 대신하지 못한다.
- L6은 수확 체감이 심하지만, 가족 앱처럼 매일 여는 앱에서는 누적된 디테일이 신뢰가 된다. 다만 L6은 L3~L5가 끝난 실물 위에서 해야 낭비가 없다 — 정적 목업을 만 번 깎는 것은 대부분 버려진다.
- 그래서 권하는 순서: 안 고르기 → L2(스케일·아이콘·타입) 제안 → 한 화면 인터랙티브 프로토타입으로 L4 맛보기 → UI 구현(L3) → 어르신 테스트(L5) → L6 상시.
